# CampusConnect — Presentation Flow

## 1. Title
**CampusConnect — See a problem? Help improve it.**
Hack Devengers 1.0

Say: “We are presenting CampusConnect, a student-focused platform designed to make campus issue reporting easier and more transparent.”

## 2. Problem
Students regularly notice broken equipment, cleanliness issues, Wi-Fi problems, leakage and lighting/safety issues. Reporting can be scattered or difficult to track.

## 3. Solution
CampusConnect provides one simple flow:
**Report → Support → Track**

## 4. How it works
1. Student reports the problem.
2. Other students can support it.
3. The issue can be viewed as Reported, In Progress or Resolved.

## 5. Features
- Responsive UI
- Issue reporting form
- Search and filters
- Photo upload
- Support/upvote
- Dashboard statistics
- Browser persistence

## 6. Technology
HTML5, CSS3, JavaScript ES6, localStorage and FileReader API.

## 7. Live demo
1. Open the dashboard.
2. Show statistics and existing reports.
3. Click “Report an Issue”.
4. Submit a sample issue.
5. Search/filter the new report.
6. Click Support.
7. Refresh and show that the report remains.

## 8. Future scope
Backend with Node.js/Express, database, authentication, admin dashboard, notifications, cloud image storage and map integration.

## 9. Closing
“CampusConnect started with a simple observation: small campus problems can have a big effect on student experience. We wanted to make reporting those problems simple, visible and actionable. Thank you.”

## Judge questions
**Is there a backend?**
“For this hackathon MVP, I used browser localStorage for persistence. A production version would use a backend API and database.”

**Why this problem?**
“We chose a relatable campus problem with a clear user flow and practical scope.”

**What did you learn?**
“I practiced DOM manipulation, event handling, form processing, localStorage, responsive UI design and converting a real-world problem into a working web application.”

**What would you build next?**
“My first priority would be authentication and a backend database, followed by an admin dashboard for campus staff.”
